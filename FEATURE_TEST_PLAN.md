# Omega's God Tweaks Feature Test Plan

Temporary feature-test proof logs use this shape:

```text
[FeatureTest] Feature Name: detail
```

Test one feature at a time by enabling only that feature and the listed dependencies. After each test, search `Player.log` for:

```text
[FeatureTest]
transpiler failed
manual patch skipped
```

The expected output column is the gameplay or data result to confirm after the matching log appears.

| Feature or toggle | Dependencies | In-game test | Expected Player.log marker | Expected output |
| --- | --- | --- | --- | --- |
| Allow Joining Multiple Religions | None | Join god A, gain piety or worship days, convert to god B, then convert back. | `[FeatureTest] Allow Joining Multiple Religions:` and `[FeatureTest] Save-Scoped Faith State:` | Previous god stays joined when enabled. Returning to a god restores saved piety, worship days, `giftRank`, and reward history from the save-scoped `GameIOContext` chunk. |
| Save-Scoped Faith State | Any feature that changes joined state | Change joined-god state, save normally, reload. Then change state without saving and reload the previous save. Reload restores only the last normally saved state. Old loose JSON state is read as a migration fallback, then saved into the context chunk on the next save. |

## Eyth / Demigod Edge Cases

These are reference-backed edge checks from `references/Elin/Chara.cs`, `ActPray.cs`, `Religion.cs`, `TraitAltar.cs`, and `Card.cs`.

| Edge case | Reference behavior checked | Dependencies | In-game test | Expected Player.log marker | Expected output |
| --- | --- | --- | --- | --- | --- |
| Current faith Eyth without Demigod blocks faith bonuses | `Chara.RefreshFaithElement` returns before adding faith elements when current faith is Eyth and element `1228` is missing. | Apply Joined God Bonuses | Make Eyth the current faith without Demigod, then refresh stats. | `[FeatureTest] Eyth / Demigod Edge Cases: current faith is Eyth without Demigod` | No `[FeatureTest] Apply Joined God Bonuses:` log for that refresh. Current and joined faith bonuses stay blocked, matching vanilla. |
| Current faith Eyth with Demigod can reach faith bonus flow | `Chara.RefreshFaithElement` only blocks Eyth when Demigod `1228` is missing. | Apply Joined God Bonuses, Allow Joining Multiple Religions | Give the player Demigod while current faith is Eyth, keep a non-Eyth joined god, then refresh stats. | `[FeatureTest] Apply Joined God Bonuses:` | Joined non-Eyth faith bonuses can apply. The Eyth-without-Demigod block log should not appear. |
| Joined non-current Eyth is skipped by joined-god loops | `Religion.Revelation` returns for Eyth and `Religion.GetGiftRank` returns `-1` for Eyth, so joined routing should not try to process Eyth as a normal reward/revelation god. | Allow Joining Multiple Religions, plus the joined feature being tested | Keep Eyth joined but non-current, then test joined bonuses, joined prayer rewards, joined prayer piety, or joined revelation routing. | `[FeatureTest] Eyth / Demigod Edge Cases: skipped joined Eyth` | No joined bonus/reward/revelation route is applied to Eyth. Other joined non-Eyth gods still behave normally. |
| Multiple prayers per day does not bypass Eyth/no-Demigod prayer branch | `ActPray.TryPray` handles Eyth without Demigod before the normal reward-check flow. | Allow Multiple Prayers Per Day | As Eyth without Demigod, pray after already praying that day. | `[FeatureTest] Prayer Flow:` with `reachedRewardCheck=False`, plus `[FeatureTest] Eyth / Demigod Edge Cases: current faith is Eyth without Demigod` | No `[FeatureTest] Allow Multiple Prayers Per Day:` log. The mod does not clear the daily prayer flag because vanilla would not reach the normal reward path. |
| Eyth artifact cleanup stays separate from duplicate cleanup | `Card.PurgeDuplicateArtifact` contains duplicate cleanup and a Demigod/Eyth deity cleanup path; `Card.PurgeEythArtifact` only runs when the player is Eyth with Demigod. | Disable Eyth Single Artifact Purge, tested separately from Allow Duplicate God Artifacts | With Demigod / Sacred Twilight active, use an Eyth altar and offer another god's artifact so vanilla marks it as Eyth-owned, then trigger artifact cleanup. Separately test a normal duplicate artifact with Allow Duplicate God Artifacts. | `[FeatureTest] Disable Eyth Single Artifact Purge:` or `[FeatureTest] Allow Duplicate God Artifacts:` | Eyth ownership cleanup and duplicate cleanup can be verified independently. Enabling one should not be mistaken for testing the other. |

Expected failure check: no test should produce `transpiler failed` or `manual patch skipped` unless you are intentionally testing a missing target path.
